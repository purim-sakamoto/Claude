## 1. 目的と範囲

### 1.1 目的
- 自社の歩み（手作業による塩化鉄製造 → プラント化 → 尿素水などの化成品）をモチーフにしたゲームで、社員が楽しみながら事業・化学に親しめるようにする
- 社内システム上で、業務の合間に短時間ずつ遊べる形で提供する

### 1.2 範囲
| 範囲内 | 範囲外（初版） |
|---|---|
| ゲーム本体（SPA） | ネイティブアプリ |
| ローカル保存・エクスポート/インポート | 課金・広告 |
| サーバ保存API（任意・仕様のみ定義） | ランキング・部署対抗（P5で検討） |
| 時代0〜6＋エンディング | 周回要素「第二創業」（P5で検討） |
| バランスシミュレータ（開発用） | 多言語対応（日本語のみ） |

### 1.3 用語
| 用語 | 意味 |
|---|---|
| ティック | ゲーム内の最小時間単位。**1ティック = 0.2秒（毎秒5ティック）** |
| 資源 | 円・金物・塩酸など、数量と上限を持つもの |
| 設備 | 建てるたびにコストが上がる建造物 |
| 社員 | 人口。職種に配属して資源を生産する |
| 技術 | 研究ptで一度だけ取得する解放要素 |
| 改善提案 | 資源で一度だけ取得する恒久強化 |
| 時代 | 進行段階（0〜6） |

## 2. 機能要件

### 2.1 資源（FR-RES）

| ID | 要件 |
|---|---|
| FR-RES-01 | 各資源は `数量`・`上限`・`毎秒増減` を持ち、画面に表示する |
| FR-RES-02 | 数量は 0 未満にならず、上限を超えない（超過分は破棄） |
| FR-RES-03 | 毎秒増減の内訳（どの設備・職種がいくら）をツールチップで表示する |
| FR-RES-04 | 未解放の資源は表示しない。初めて入手した時点で表示する |
| FR-RES-05 | 上限のない資源（円・研究pt等）も定義できる |
| FR-RES-06 | 消費が生産を上回る資源は赤字表示し、0到達までの時間を表示する |

**資源一覧（初版想定）**

| 時代 | 資源 | 概要・入手 |
|---|---|---|
| 0 | 円 | 製品の販売で得る。給与・建設に使う |
| 0 | 金物（鉄くず） | クリック／回収員で集める |
| 0 | 塩酸 | 円で仕入れる → 後に自社製造 |
| 0 | 塩化鉄液 | 金物＋塩酸から製造（主力商品） |
| 1 | 水素 | 溶解の副産物。最初は捨てる→回収設備で燃料に |
| 1 | 信用 | 納品実績で増加。取引条件・採用に影響 |
| 1 | 技術（研究pt） | 研究員が生産 |
| 2 | 電力 | 発電設備。プラント系の稼働に必要（不足時は稼働率低下） |
| 2 | 鋼材 | 設備建設用の資材 |
| 2 | 塩化第二鉄 | 塩素化工程で高付加価値化（水処理用凝集剤） |
| 3 | 純水 | 尿素水・薬剤の原料 |
| 3 | アンモニア／尿素 | 尿素水の原料 |
| 3 | 尿素水 | 主力商品その2（冬季需要↑） |
| 3 | 輸送力 | ローリー台数。販売量の上限に関係 |
| 4 | 拠点 | 国内外の拠点数（上限資源の倍率等） |
| 4 | ブランド | 長期倍率系の資源 |
| 5 | 月面鉄／軌道資材 | 宇宙での建設資材 |
| 5 | ロケット燃料 | 水素から製造（序盤の副産物がここで化ける） |
| 6 | 恒星エネルギー | 恒星炉で生産 |
| 6 | 星間物質 | 星間雲から回収（塩化水素・尿素を含む） |

### 2.2 クリック行動（FR-ACT）
| ID | 要件 |
|---|---|
| FR-ACT-01 | 時代0では「金物を集める」「手で溶かす」「売りに行く」の3ボタンで進行できる |
| FR-ACT-02 | クリック行動は自動化（社員・設備）で不要になっていく。終盤でクリック必須の操作は作らない |
| FR-ACT-03 | 連打対策は不要だが、クリック1回の効果は設備生産の伸びに対して相対的に小さくなる設計とする |

### 2.3 設備（FR-BLD）
| ID | 要件 |
|---|---|
| FR-BLD-01 | 設備のコストは `基本コスト × 倍率^所有数`（倍率は設備ごと 1.10〜1.20、標準 1.15） |
| FR-BLD-02 | 設備は生産・消費・上限増加・倍率付与のいずれか/複数の効果を持つ |
| FR-BLD-03 | 消費を伴う設備は**稼働ON/OFF**および**稼働数の調整**ができる |
| FR-BLD-04 | 必要資源が不足すると、その設備は比例的に稼働率が下がる（全停止ではなく按分） |
| FR-BLD-05 | 解放条件（技術・時代・他設備数）を満たしたものだけ表示する |
| FR-BLD-06 | ボタンには不足資源と「あと何秒で建設可能か」を表示する |
| FR-BLD-07 | 売却（解体）は所有数を1減らし、コストの一部を返す（初版は返却率50%） |
| FR-BLD-08 | 各時代に**メガ設備**（段階建設型、5〜20段）を1つ置き、時代の壁とする |

**設備の例（初版で約50種）**

| 時代 | 設備 | 主な効果 |
|---|---|---|
| 0 | 手桶 / 素焼きの釜 | 手溶解の効率↑ |
| 0 | 物置 | 金物・塩酸の上限↑ |
| 1 | 作業小屋 / 社宅 | 社員の上限↑ |
| 1 | 鉄製の釜・換気塔 | 塩化鉄液の自動生産 |
| 1 | 水素回収管 | 水素を回収（時代1後半） |
| 2 | 反応槽 / 塩素化設備 | 塩化鉄液→塩化第二鉄 |
| 2 | タンクヤード / 発電設備 / 品質管理室 | 上限・電力・品質倍率 |
| 2 | **メガ：第一プラント** | 完成で時代3へ |
| 3 | 純水装置 / 尿素溶解槽 / 充填ライン | 尿素水の生産 |
| 3 | ローリー車庫 / 配送センター | 輸送力 |
| 3 | **メガ：総合物流網** | 完成で時代4へ |
| 4 | 営業所 / 港湾ターミナル / 海外工場 / 中央研究所 | 拠点・ブランド・研究 |
| 4 | **メガ：宇宙事業部の設立（打上げ施設）** | 完成で時代5へ |
| 5 | 月面溶解プラント / 小惑星採掘船 / 金星浮遊プラント / 軌道上タンク | 宇宙資源 |
| 5 | **メガ：軌道エレベーター** | 完成で時代6へ |
| 6 | 恒星炉 / 星間雲回収網 / 銀河水処理網 / 恒星間ローリー | 恒星・銀河スケール |
| 6 | **メガ：始まりの釜** | 完成でエンディング |

### 2.4 社員と配属（FR-STF）
| ID | 要件 |
|---|---|
| FR-STF-01 | 社員数の上限は住居系設備で決まる。上限に空きがあり、信用が一定以上なら一定間隔で1人ずつ入社する |
| FR-STF-02 | 社員は毎秒**給与（円）**を消費する。円が0になると全体の生産効率が下がる（士気低下）。社員は離職しない（ストレスを与えすぎない） |
| FR-STF-03 | 職種：職人／回収員／営業／研究員／運転員／品質管理／物流／（時代5〜）宇宙技師 |
| FR-STF-04 | 配属は＋／−ボタンで変更でき、一括（＋5、全員、解除）にも対応する |
| FR-STF-05 | 社員は経験（勤続）で微増する熟練度ボーナスを持つ（全体平均で計算、個人管理はしない） |
| FR-STF-06 | 時代5以降、社員数が多くなりすぎないよう「部署」単位（1部署＝100人分）に表示を集約する |

### 2.5 技術開発（FR-TEC）
| ID | 要件 |
|---|---|
| FR-TEC-01 | 技術は研究pt（＋一部資源）で取得し、設備・職種・改善提案・時代を解放する |
| FR-TEC-02 | 技術は前提技術を持つツリー構造（初版約60件） |
| FR-TEC-03 | 取得済み・取得可能・未解放（前提のみ見える）を区別して表示する |
| FR-TEC-04 | 各技術に短いフレーバーテキスト（化学ネタ）を付ける |

技術ツリーの幹（例）：
`酸の扱い → 換気 → 水素の性質 → 塩素化 → 計装 → 品質管理 → 水処理化学 → 純水 → 尿素合成 → 物流最適化 → 国際規格 → 推進剤 → 宇宙冶金 → 大気化学（金星） → 核融合 → 恒星元素合成 → 星間化学 → 宇宙論的反応工学`

### 2.6 改善提案（FR-UPG）
| ID | 要件 |
|---|---|
| FR-UPG-01 | 一度だけ購入できる恒久強化（初版約80件）。例：「保護手袋」手溶解+50%／「タンクの蓋」上限+25% |
| FR-UPG-02 | 効果は倍率（乗算）または加算で、どちらかをデータで指定する |
| FR-UPG-03 | 購入済みの改善提案は一覧で確認できる |

### 2.7 取引（FR-TRD）
| ID | 要件 |
|---|---|
| FR-TRD-01 | 製品（塩化鉄液・塩化第二鉄・尿素水など）は「出荷」で円に換える。営業・物流による自動出荷も持つ |
| FR-TRD-02 | 取引先ごとに 欲しい製品・単価・信用条件 を持ち、信用が上がると単価・量が改善 |
| FR-TRD-03 | 季節（四半期）で需要が変わる：夏＝水処理系↑、冬＝尿素水↑ |
| FR-TRD-04 | 時代6では異星文明（例：「ケイ素生命の商会」）が取引先として登場する |

### 2.8 暦とイベント（FR-CAL）
| ID | 要件 |
|---|---|
| FR-CAL-01 | ゲーム内の暦：1四半期＝実時間 約20分、1年＝約80分（調整可） |
| FR-CAL-02 | ランダムイベント：**良いものを中心**とする（例：「掘り出し物の金物が届いた」クリックで回収）。悪いイベントは軽微かつ短時間のみ |
| FR-CAL-03 | イベントは放置中に取り逃しても大きく不利にならない |

### 2.9 理念（FR-PHL、時代4〜）
| ID | 要件 |
|---|---|
| FR-PHL-01 | ブランドを消費して「理念」を掲げると、全体倍率などの強化を得る（Kittens の宗教に相当） |
| FR-PHL-02 | 理念は複数段階で、後半は宇宙規模の効果（例：「全ての星は取引先」） |

### 2.10 ミッション・社史・実績（FR-PRG）
| ID | 要件 |
|---|---|
| FR-PRG-01 | 画面上部に**次の目標を常に1つ**表示する（例：「塩化鉄液を10リットル作る」） |
| FR-PRG-02 | 時代移行・重要イベントで「社史」タブに架空の年表が1行追加される |
| FR-PRG-03 | 実績（初版約50件）。一部は小さな恒久ボーナス付き |
| FR-PRG-04 | 統計画面：プレイ時間、累計生産量、建設数、オフライン進行時間 等 |
| FR-PRG-05 | エンディング到達時に、エンディング演出と「クリア日数」を表示する |

### 2.11 オフライン進行（FR-OFF）
| ID | 要件 |
|---|---|
| FR-OFF-01 | 閉じている間の進行を、再訪時に一括計算して反映する |
| FR-OFF-02 | 効率：経過**12時間までは100%**、12〜72時間は25%、72時間超は進行なし（パラメータで変更可） |
| FR-OFF-03 | 再訪時に「留守中の報告書」（主な資源の増減、建設可能になった設備）を表示する |
| FR-OFF-04 | 計算は数秒以内に終わること（ティックをまとめた粗い刻みで計算してよい） |
| FR-OFF-05 | 端末時刻を戻すなどの不正で大きな負の経過が出た場合は 0 として扱う |

### 2.12 セーブ（FR-SAV）
| ID | 要件 |
|---|---|
| FR-SAV-01 | 30秒ごと・タブ非表示時・重要操作後に自動保存（localStorage） |
| FR-SAV-02 | セーブデータは**バージョン番号**を持ち、旧版からの移行処理を実装する |
| FR-SAV-03 | テキスト（Base64圧縮）でのエクスポート/インポート |
| FR-SAV-04 | （任意）サーバ保存API：`GET /api/idle/save`、`PUT /api/idle/save`（本文はセーブ文字列、上限256KB）。ユーザー特定は社内システムのログインセッションを使用 |
| FR-SAV-05 | ローカルとサーバで食い違う場合、更新日時と進行度を並べて表示し、利用者に選ばせる |
| FR-SAV-06 | データ全消去（確認2回） |

### 2.13 画面・UI（FR-UI）
| ID | 要件 |
|---|---|
| FR-UI-01 | レイアウト：左＝資源一覧、中央＝タブ、上部＝ミッション・暦、下部＝ログ |
| FR-UI-02 | タブ：**現場**（設備）／**人事**（社員）／**技術開発**／**改善提案**／**取引**／**理念**／**宇宙事業部**／**社史**／**実績・統計**／**設定**（解放順に表示） |
| FR-UI-03 | 大きな数は日本語の命数で表示：万・億・兆・京・垓…**無量大数（10^68）**まで。設定で「1.23e45」形式にも切替可 |
| FR-UI-04 | ライト/ダークテーマ。時代5以降は背景が宇宙風に変化する（演出、設定でOFF可） |
| FR-UI-05 | 音なしが既定（社内利用のため）。効果音は設定でON |
| FR-UI-06 | 「業務モード」：ワンクリックで画面を地味な表示に切り替える（ゲーム進行は継続） |
| FR-UI-07 | 横幅 1024px 以上で快適に、360px（スマホ）でも最低限操作可能 |

## 3. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-01 | 動作環境 | 社内標準の Edge / Chrome 最新2版。※スマホ対応の要否は要確認 |
| NFR-02 | 性能 | 通常時 CPU 使用率を低く保つ（描画は変化分のみ、最大10fps）。タブ非表示時は描画停止し、復帰時に経過分を計算 |
| NFR-03 | 性能 | 初回読込 1MB 以下（gzip後）、外部CDN・外部フォントへの依存なし（社内ネットワーク前提） |
| NFR-04 | 数値 | 倍精度浮動小数で扱う。最大値は 1e300 未満に収まるよう設計（巨大数ライブラリは不要） |
| NFR-05 | 保守性 | 資源・設備・技術・改善提案・テキストは**データファイル（TypeScript/JSON）で定義**し、ロジックと分離。テキストの差し替えは非エンジニアでも可能に |
| NFR-06 | 組み込み | 静的ファイル一式（HTML/JS/CSS）として出力し、任意のパス配下・iframe 内で動作する |
| NFR-07 | セキュリティ | 外部送信なし（サーバ保存APIを除く）。個人情報は保持しない。CSP に対応（`eval` 不使用） |
| NFR-08 | アクセシビリティ | キーボード操作可能、色だけに頼らない表示、文字サイズ変更に追従 |
| NFR-09 | 品質 | ゲームロジックの単体テスト、セーブ移行のテスト、バランスシミュレーションをCIで実行 |

### 技術スタック（案）
- TypeScript + Vite（静的ビルド）
- UI：軽量フレームワーク（Preact または Svelte）※社内の既存技術に合わせて調整
- テスト：Vitest
- バックエンド（任意）：社内システム側の既存基盤に保存APIを追加

## 4. バランス要件

### 4.1 クリア時間
| プレイスタイル | 想定 | 目標クリア日数 |
|---|---|---|
| ヘビー | 1日に合計2時間以上アクティブ、こまめに再訪 | **5日前後** |
| ふつう | 1日に3〜5回、各5〜10分 | **8日前後** |
| ライト | 1日に2回（朝・夕）、各5分 | **14日以内** |

### 4.2 時代ごとの目安（「ふつう」プレイ、累計経過時間）
| 時代到達 | 目安 |
|---|---|
| 時代1 | 30分〜1時間 |
| 時代2 | 0.5日 |
| 時代3 | 1.5日 |
| 時代4 | 3.5日 |
| 時代5 | 5.5日 |
| 時代6 | 7日 |
| エンディング | 8日 |

### 4.3 設計ルール
| ID | ルール |
|---|---|
| BAL-01 | 再訪するたびに「何か1つは買える/解放できる」状態を作る（再訪間隔 3〜8時間を想定） |
| BAL-02 | 時代の後半は伸びが鈍化し、次の時代の最初の解放で大きく伸びる（壁と突破の気持ちよさ） |
| BAL-03 | 放置最適解と能動最適解の差は最大でも2倍程度に抑える（ライト層が置いていかれない） |
| BAL-04 | 時代の数量スケール目安：時代0＝〜千、時代2＝〜億、時代4＝〜京、時代6＝〜無量大数 |
| BAL-05 | **バランスシミュレータ**：3種のプレイスタイルを模した自動プレイ（貪欲法＋再訪間隔）でクリア日数を算出し、上表から±20%を超えたらCIで警告する |
| BAL-06 | 詰み防止：どの状態からでも（円が0でも）放置で必ず回復できる。資源・設備のロック状態を作らない |

## 6. 受け入れ基準

1. 新規開始からエンディングまで、ルールどおりに通しでプレイできる（詰みなし）
2. バランスシミュレータで、3スタイルすべてが 4.1 の目標範囲内でクリアする
3. 社内テストプレイヤー（5名以上）の実測クリア日数が 5〜14日に収まる
4. 旧バージョンのセーブデータが最新版で読み込める
5. 社内標準ブラウザで、2時間連続起動しても動作が重くならない（メモリ増加なし）
6. 実在社名・人物名・商標を含まない（テキストチェックリストで確認）

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| 進行が速すぎる/遅すぎる | シミュレータと社内テストで調整。全パラメータはデータファイルで変更可能 |
| 業務時間中のプレイが問題視される | 業務モード・音なし既定・放置中心の設計。社内ルールに合わせて運用 |
| 社史の扱いが不適切になる | 架空の年表とし、実エピソードは担当部署の確認を経て差し替え |
| セーブ消失 | 自動保存＋エクスポート＋（任意）サーバ保存 |
| 後半の数値が巨大で分かりにくい | 命数表示＋「前回比×何倍」の表示で成長実感を出す |
