## 1. 目的と範囲

### 1.1 目的
- 塩化鉄の手作業製造から始まる**製造プロセスの発展**をモチーフに、宇宙規模まで到達するインクリメンタルゲームを作る
- 社内で実験的に公開し、遊びながら製造工程・化学に親しめるものにする

### 1.2 範囲
| 範囲内 | 範囲外 |
|---|---|
| ゲーム本体（静的 HTML/CSS/JS） | サーバ側処理・サーバ保存 |
| ブラウザ保存（localStorage）とエクスポート/インポート | ランキング・ユーザー間の比較 |
| 時代0〜6＋エンディング | 社史・会社固有のエピソード |
| 開発用 Python ツール（バランスシミュレータ・データ検証） | 周回要素（クリア後の追加として将来検討） |
| 別アプリから呼び出されるための最低限の作法（§5） | スマホ専用UI、多言語対応 |

### 1.3 用語
| 用語 | 意味 |
|---|---|
| ティック | 最小時間単位。**1ティック＝0.2秒（毎秒5ティック）** |
| 資源 | 数量と上限を持つもの（鉄くず・塩酸・円など） |
| 設備 | 建てるたびにコストが上がる建造物 |
| 人手 | 人口。配属して資源を生産する |
| 技術 | 研究ptで一度だけ取得する解放要素 |
| 改善 | 資源で一度だけ取得する恒久強化 |
| 時代 | 進行段階（0〜6）。画面には名称を表示しない |
| 開示 | 画面要素が条件を満たして初めて出現すること |

## 2. 機能要件

### 2.0 導入と画面の開示（FR-INT）
| ID | 要件 |
|---|---|
| FR-INT-01 | タイトル画面は持たない。初回起動時、黒地に一行「暗い。」とボタン〔手探りする〕だけを表示する |
| FR-INT-02 | 導入シーケンス（企画書 §3）はデータ（ステップ＝ログ文・出現ボタン・遷移条件）で定義し、文言を差し替え可能にする |
| FR-INT-03 | 画面要素は開示条件を満たすまで描画しない：資源欄 → 人数 → タブ（現場）→ 暦 → 作業メモ → 工程図 → 他タブ…の順 |
| FR-INT-04 | 要素の開示はフェードイン（0.5〜1秒）。設定で演出OFF可 |
| FR-INT-05 | 未判明の資源は仮の名前（`? 液`、`緑の液`）で表示し、条件達成で正式名称に置き換える |
| FR-INT-06 | 60秒無操作の場合、次の行動を示唆するヒントを**ログに1行だけ**出す（ポップアップは出さない） |
| FR-INT-07 | 時代ごとに配色・文体が変わる（暗がり：黒／工場：灰白／星：紺）。時代名そのものは表示しない |
| FR-INT-08 | エンディング後は画面が暗転し「暗い。」〔沈める〕だけが残る。押すとクレジットと統計を表示 |

### 2.0a 最初の15分のフック（FR-HOK）
呼び出し元アプリのボタン「タイキ薬品工業　ミニゲーム」から開かれる前提で、最初は小さなミニゲームに見せ、約15分で奥行きに気づかせる（企画書 §3.5）。

| ID | 要件 |
|---|---|
| FR-HOK-01 | 開始〜約12分は、手作業・人手・釜の範囲の語彙と画面要素だけを出す。宇宙・恒星などの語は出さない |
| FR-HOK-02 | 12〜15分（ふつうの操作ペース）で次の3つが**ほぼ同時期**に起きるよう数値を調整する：塩素化による液色の変化（緑→赤褐色）／技術画面の開示／ログ「夜、釜の液面に星が映っていた。」 |
| FR-HOK-03 | 技術画面では、前提が満たされていない遠い技術も**名前だけ**（灰色・説明なし・コスト非表示）表示し、ツリーの奥行きを見せる。時代5〜6の技術名を少なくとも3つ含める |
| FR-HOK-04 | 約15分で作業メモ（次の目標）を開示し、ログに一度だけ「留守のあいだも、釜は溶かし続ける。」と出してオフライン進行を知らせる |
| FR-HOK-05 | フック関連の出来事の発生時刻（開始からの経過秒）を統計に記録し、テストで確認できるようにする |

### 2.1 資源（FR-RES）
| ID | 要件 |
|---|---|
| FR-RES-01 | 各資源は `数量`・`上限`・`毎秒増減` を持ち、画面に表示する |
| FR-RES-02 | 数量は 0 未満にならず、上限を超えない（超えた分は捨てる） |
| FR-RES-03 | 毎秒増減の内訳（設備・配属ごと）をツールチップで表示する |
| FR-RES-04 | 未開示の資源は表示しない |
| FR-RES-05 | 上限のない資源（円・研究pt等）も定義できる |
| FR-RES-06 | 減り続けている資源は赤で表示し、0 になるまでの時間を出す |

**資源一覧（初版想定）**

| 時代 | 資源 | 概要 |
|---|---|---|
| 0 | 鉄くず | 〔拾う〕／回収の配属で集める |
| 0 | 塩酸 | 最初は `? 液`。〔酸を買う〕で判明。のちに自前で確保 |
| 0 | 緑の液 → 塩化第一鉄液 | 鉄くず＋塩酸。時代1で正式名称に |
| 0 | 円 | 製品を渡して得る。給与・建設に使う |
| 1 | 塩化第二鉄液 | 塩化第一鉄液を塩素化（赤褐色）。主力 |
| 1 | 水素 | 溶解の副産物。時代4まで捨てるだけ、時代5でロケット燃料に |
| 1 | 信用 | 納品で増える。取引条件・人手の集まりやすさに影響 |
| 1 | 技術（研究pt） | 研究の配属で生産 |
| 2 | 電力 | 工場系設備の稼働に必要。不足すると稼働率が下がる |
| 2 | 品質 | 分析で上がる。製品単価に倍率 |
| 2 | 使用済み液 | 取引先から戻るエッチング廃液。循環（FR-CIR）の原料 |
| 2 | 銅 | 脱銅で回収 |
| 2 | ポリシリカ鉄 | アルミを含まない凝集剤 |
| 3 | 純水 | 尿素水・調合の原料 |
| 3 | 尿素 | 尿素水の原料（仕入れ → 時代4で合成） |
| 3 | 高品位尿素水（AUS32） | 第二の主力。冬に需要↑。**商標名は使わない** |
| 3 | 各種薬品 | 硫酸・苛性ソーダ・次亜塩素酸ソーダ等。調合台で使う |
| 3 | 輸送力 | 荷姿の段階と台数で決まる |
| 4 | アンモニア・CO₂ | 尿素合成の原料 |
| 4 | 循環率 | 物質収支がどれだけ閉じているか（%）。全体倍率 |
| 5 | 月面鉄・軌道資材・ロケット燃料 | 宇宙での原料・資材・推進剤 |
| 6 | 恒星エネルギー・星間物質 | 恒星炉・星間雲からの資源 |

### 2.2 クリック行動（FR-ACT）
| ID | 要件 |
|---|---|
| FR-ACT-01 | 時代0はボタン1つから始まり、導入シーケンスに従ってボタンが増える |
| FR-ACT-02 | クリック行動は配属・設備で自動化されていく。時代2以降、クリック必須の操作は作らない |

### 2.3 設備（FR-BLD）
| ID | 要件 |
|---|---|
| FR-BLD-01 | コスト＝`基本コスト × 倍率^所有数`（倍率は設備ごとに 1.10〜1.20、標準 1.15） |
| FR-BLD-02 | 効果：生産・消費・上限増加・倍率付与のいずれか/複数 |
| FR-BLD-03 | 消費を伴う設備は稼働数を調整できる（0〜所有数） |
| FR-BLD-04 | 原料が足りない場合、その設備は足りている割合だけ稼働する（全停止にはしない） |
| FR-BLD-05 | 解放条件（技術・時代・他設備数）を満たしたものだけ表示する |
| FR-BLD-06 | ボタンに不足資源と「あと何秒で建てられるか」を表示する |
| FR-BLD-07 | 解体すると所有数が1減り、コストの50%が戻る |
| FR-BLD-08 | 各時代に**大型設備**（5〜20段階で建設）を1つ置き、次の時代への壁とする |

**設備の例（初版で約50種）**

| 時代 | 設備 | 主な効果 |
|---|---|---|
| 0 | 壺 / 釜 | 溶解の上限・効率↑ |
| 0 | 物置 | 鉄くず・塩酸の上限↑ |
| 1 | 作業小屋 / 寮 | 人手の上限↑ |
| 1 | 鉄の釜・換気口 | 塩化第一鉄液の自動生産 |
| 1 | 塩素化槽 | 塩化第一鉄液→塩化第二鉄液 |
| 1 | 希釈台 | 酸の希釈・小分け（調合の入口） |
| 2 | 分析室 | 品質↑ |
| 2 | 濃縮設備 | 濃度グレード↑（単価↑） |
| 2 | 脱銅設備 | 使用済み液 → 再生液＋銅 |
| 2 | ポリシリカ鉄設備 | 凝集剤の生産 |
| 2 | 計装盤 | バッチ→連続運転（配属不要の自動稼働） |
| 2 | **大型：連続プラント** | 完成で時代3へ |
| 3 | 純水装置 / 尿素溶解槽 / 調整槽 / 充填ライン | 尿素水の生産 |
| 3 | 調合ライン | 調合品の自動生産 |
| 3 | 大型タンク / ローリー / 配送拠点 | 上限・輸送力 |
| 3 | **大型：一貫生産ライン** | 完成で時代4へ |
| 4 | 尿素合成塔 / 水素回収系 / 塩酸回収系 / 排水再生系 | 物質収支を閉じる |
| 4 | **大型：閉じた系** | 循環率が基準に達し完成で時代5へ |
| 5 | 月面溶解プラント / 小惑星溶解船 / 金星浮遊プラント / 軌道上タンク | 宇宙資源 |
| 5 | **大型：軌道エレベーター** | 完成で時代6へ |
| 6 | 恒星炉 / 星間雲回収網 / 銀河水処理網 / 恒星間ローリー | 恒星・銀河規模 |
| 6 | **大型：始まりの釜** | 完成でエンディング |

### 2.4 人手と配属（FR-STF）
| ID | 要件 |
|---|---|
| FR-STF-01 | 人数の上限は住居系設備で決まる。上限に空きがあり信用が条件を満たせば、一定間隔で1人ずつ増える |
| FR-STF-02 | 人手は毎秒給与（円）を消費する。円が0になると全体の生産効率が下がる。人手が減ることはない |
| FR-STF-03 | 配属：溶解／回収／運転／分析／調合／物流／研究／（時代5〜）宇宙作業。時代0〜1では「手伝い」とだけ表示 |
| FR-STF-04 | 配属は＋／−と一括（＋5、全員、解除）で変更できる |
| FR-STF-05 | 時代2以降、計装・自動化により「配属不要の設備」が増え、人手は研究・品質・物流に回っていく（自動化の手応え） |
| FR-STF-06 | 人数が多くなったら「班」単位（1班＝100人）で集約表示する |

### 2.5 技術（FR-TEC）
| ID | 要件 |
|---|---|
| FR-TEC-01 | 研究pt（＋一部資源）で取得し、設備・配属・改善・時代を解放する |
| FR-TEC-02 | 前提技術を持つツリー構造（初版約60件） |
| FR-TEC-03 | 取得済み・取得可能・未解放（名前だけ見える）を区別して表示する |
| FR-TEC-04 | 各技術に短い化学のフレーバーテキストを付ける |

技術ツリーの幹（例）：
`酸の扱い → 換気 → 塩素化 → 希釈 → 比重 → 分析 → 濃縮 → 脱銅 → 循環 → 凝集とシリカ → 計装 → 連続運転 → 純水 → 尿素の溶解 → 多項目分析 → 充填と荷姿 → 調合 → 尿素合成 → 物質収支 → 推進剤 → 宇宙冶金 → 大気化学 → 核融合 → 恒星元素合成 → 星間化学 → 宇宙反応工学`

### 2.6 改善（FR-UPG）
| ID | 要件 |
|---|---|
| FR-UPG-01 | 一度だけ購入できる恒久強化（初版約80件）。例：「厚手の手袋」溶解+50%／「タンクの蓋」上限+25%／「比重計」品質+10% |
| FR-UPG-02 | 効果は乗算または加算をデータで指定する |
| FR-UPG-03 | 購入済みの一覧を見られる |

### 2.7 取引（FR-TRD）
| ID | 要件 |
|---|---|
| FR-TRD-01 | 製品は「出荷」で円に換える。物流の配属・設備で自動出荷 |
| FR-TRD-02 | 取引先ごとに欲しい製品・単価・信用条件を持つ。信用が上がると単価・量が改善 |
| FR-TRD-03 | 季節で需要が変わる：夏＝凝集剤↑、冬＝尿素水↑ |
| FR-TRD-04 | 取引先の例：浄水場・下水処理場（凝集剤）、電子部品の工場（エッチング用の塩化第二鉄液。使用済み液を返してくる）、運送会社（尿素水）、農家（ポリシリカ鉄の汚泥が田畑に還る）、食品工場（調合品） |
| FR-TRD-05 | 時代6では異星の商会が取引先に加わる |
| FR-TRD-06 | 荷姿の段階（手渡し→ポリ缶→BIB→ドラム→コンテナ→ローリー→軌道輸送→恒星間輸送）で1回の出荷上限が増える |

### 2.8 調合台（FR-MIX、時代1〜）
| ID | 要件 |
|---|---|
| FR-MIX-01 | 仕入れ薬品と純水で、希釈・混合・溶解・小分けを行い多品目を作れる |
| FR-MIX-02 | 取引先から小口注文（「◯◯を△%で□缶」）が届き、満たすと円と信用を得る。取り逃しても不利にならない |
| FR-MIX-03 | 調合ライン（時代3）を建てると注文を自動処理する |

### 2.9 循環（FR-CIR、時代2〜）
| ID | 要件 |
|---|---|
| FR-CIR-01 | 塩化第二鉄液を販売した取引先から、一定割合の使用済み液が戻ってくる |
| FR-CIR-02 | 使用済み液は脱銅設備で再生液と銅に分かれる |
| FR-CIR-03 | 時代4で「循環率」（水素・塩酸・銅・水の回収割合の総合値）を表示し、全体倍率にする |
| FR-CIR-04 | 循環率は工程図上で、回収されていない流れ（捨てている物質）を点線で示す |

### 2.10 工程図（FR-FLW、時代1後半〜）
| ID | 要件 |
|---|---|
| FR-FLW-01 | 所有設備から製造プロセスのフロー図を自動生成して表示する（SVG） |
| FR-FLW-02 | 流れの太さ＝毎秒量、赤＝ボトルネック（原料不足で稼働率が下がっている工程） |
| FR-FLW-03 | 図のノードをクリックすると該当設備の画面に移動する |
| FR-FLW-04 | 時代が進むと図は抽象化・集約される（時代5以降は「月」「金星」などの拠点単位） |

### 2.11 暦とイベント（FR-CAL）
| ID | 要件 |
|---|---|
| FR-CAL-01 | 1季節＝実時間 約20分、1年＝約80分（調整可） |
| FR-CAL-02 | ランダムイベントは良いものが中心（例：「質のいい鉄くずが届いた」クリックで回収）。悪いものは軽微・短時間 |
| FR-CAL-03 | 放置中にイベントを取り逃しても大きく不利にならない |

### 2.12 作業メモ・実績・統計（FR-PRG）
| ID | 要件 |
|---|---|
| FR-PRG-01 | 「作業メモ」（次の目標を1つ表示）は時代1の途中で開示する。それ以前は目標表示を一切出さない |
| FR-PRG-02 | 実績（初版約50件）。一部は小さな恒久ボーナス付き |
| FR-PRG-03 | 統計：プレイ時間、累計生産量、建設数、オフライン進行時間、循環率の推移 等 |
| FR-PRG-04 | エンディング到達時に、クリアまでの日数とプレイ時間を表示する |

### 2.13 オフライン進行（FR-OFF）
| ID | 要件 |
|---|---|
| FR-OFF-01 | 閉じている間の進行を、再訪時にまとめて計算して反映する |
| FR-OFF-02 | 効率：経過**12時間までは100%**、12〜72時間は25%、72時間超は進行なし（パラメータで変更可） |
| FR-OFF-03 | 再訪時に「留守中の記録」（主な資源の増減、建てられるようになった設備）を表示する |
| FR-OFF-04 | 計算は数秒以内に終わること（粗い刻みでまとめて計算してよい） |
| FR-OFF-05 | 端末時刻を戻すなどで経過時間が負になった場合は0として扱う |

### 2.14 セーブ（FR-SAV）
| ID | 要件 |
|---|---|
| FR-SAV-01 | 30秒ごと・タブ非表示時・重要操作の後に localStorage へ自動保存 |
| FR-SAV-02 | セーブデータにバージョン番号を持たせ、旧版からの移行処理を実装する |
| FR-SAV-03 | テキスト（圧縮＋Base64）でエクスポート/インポートできる（別PC・別ブラウザへの引っ越し用） |
| FR-SAV-04 | データ全消去（2回確認） |
| FR-SAV-05 | 保存キーにはゲームID（例：`hitotsu-no-kama`）を前置し、同じドメインの他アプリと衝突しないようにする |

### 2.15 画面（FR-UI）
| ID | 要件 |
|---|---|
| FR-UI-01 | 最終レイアウト：左＝ログ、中央＝タブ、右＝資源一覧、上部＝作業メモ・暦。導入時はログとボタンだけ |
| FR-UI-02 | タブ（開示順）：現場／人手／技術／改善／取引／調合台／工程図／空／実績・統計。設定は最初から右下の小さな歯車のみ |
| FR-UI-03 | 大きな数は日本語の命数で表示：万・億・兆・京・垓…無量大数（10^68）まで。設定で指数表記にも切替可 |
| FR-UI-04 | 配色は時代に連動（FR-INT-07）。設定でライト/ダーク固定も選べる |
| FR-UI-05 | 効果音は既定で無し（設定でON） |
| FR-UI-06 | 横幅 1024px 以上で快適に、360px でも最低限操作できる |

## 3. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-01 | 動作環境 | Chrome / Edge の最新版。PCブラウザを主対象とする |
| NFR-02 | 性能 | 描画は変化した部分のみ、最大10fps。タブ非表示時は描画を止め、復帰時に経過分を計算 |
| NFR-03 | 軽さ | 合計 1MB 以下。外部CDN・外部フォントに依存しない |
| NFR-04 | 数値 | 倍精度浮動小数で扱い、最大値は 1e300 未満に収まるよう設計（巨大数ライブラリ不要） |
| NFR-05 | 保守性 | 資源・設備・技術・改善・テキストは **JSON データ**で定義し、ロジックと分離する |
| NFR-06 | 構成 | ビルド不要。HTML/CSS/JS（ES Modules）の静的ファイル一式 |
| NFR-07 | セキュリティ | 外部への通信なし。個人情報を保持しない。`eval` 不使用 |
| NFR-08 | アクセシビリティ | キーボード操作可能、色だけに頼らない表示 |
| NFR-09 | 品質 | ゲームロジックの単体テスト、セーブ移行テスト、Python によるデータ検証とバランスシミュレーション |

### 3.1 構成（案）
```
incremental_game/
  index.html            … エントリ（これを開けば遊べる）
  css/
  js/
    engine/             … ティック・資源計算・セーブ・オフライン進行
    ui/                 … 描画・開示演出・工程図
    main.js
  data/                 … resources.json, buildings.json, techs.json, upgrades.json, texts.json, intro.json
  tools/                … Python
    validate_data.py    … 参照切れ・到達不能・循環依存のチェック
    simulate.py         … バランスシミュレータ（3プレイスタイルのクリア日数を算出）
  docs/
```
- ゲームの計算式は JS と Python の両方に実装するため、**式は単純に保ち、データ側に寄せる**。両者の一致を確かめるテスト（同じ初期状態から N ティック進めて結果を比較）を用意する

## 6. 受け入れ基準

1. 新規開始からエンディングまで通しでプレイでき、詰みがない
2. `simulate.py` で3スタイルすべてが §4.1 の目標範囲内でクリアする
3. 社内テストプレイヤーの実測クリア日数が 5〜14日に収まる
4. 旧バージョンのセーブデータが最新版で読み込める
5. 2時間連続で開いていても重くならない（メモリが増え続けない）
6. 会社名・人名・地名・商標（AdBlue® 等）を含まない
7. 説明なしで導入シーケンス（〔釜を据える〕まで）を、テストプレイヤー全員が15分以内に突破できる
8. 別アプリから iframe／リンクで呼び出して動作する
9. テストプレイヤーが、ふつうのペースで12〜18分の間にフック（FR-HOK-02）に到達する。15分以上遊んだ人の過半数が、翌日以降もう一度開く

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| 進行が速すぎる/遅すぎる | シミュレータと社内テストで調整。全パラメータは JSON で変更可 |
| 説明がなく初見で迷う | 60秒無操作ヒント（FR-INT-06）。テストで突破時間を計測 |
| JS と Python の計算がずれる | 式を単純に保ち、両者の一致テストを用意 |
| 後半の数値が巨大で分かりにくい | 命数表示＋「前回比×何倍」の表示で成長を実感させる |
| セーブ消失（ブラウザのデータ削除など） | エクスポート機能と、設定画面での定期エクスポートの案内 |
