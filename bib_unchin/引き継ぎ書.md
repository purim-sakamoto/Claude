## 4. BIB運賃付け合わせ：照合ロジック（案）

既存の「運賃チェックシート ver.0.02」（xlsm マクロ）と「運賃付け合わせ ver.0.02」（xlsx 数式）の中身を解析し、両者を1つにまとめたものです。

### 4.1 前処理（既存マクロと同じ）
1. 12401 と 12412 の CSV を連結する。
2. 伝票種類が「在庫」以外の行を除外する。
3. 運送会社名が「引取」「自社便」の行を除外する（※ 例外リストに寄せてもよい）。

### 4.2 1対1チェック（受注番号でまとめる）
- 受注番号ごとに行をまとめる。
  - **商品行** = 重量 > 0 の行
  - **運賃行** = それ以外（商品名「運賃（製品）」、重量 0）
- 判定:
  - 商品1・運賃1 → 単価チェックへ
  - 運賃行なし → 「運賃なし」（例外リストにあれば OK）
  - 運賃行が2つ以上、または商品行なしの運賃だけ → 「要確認」

> 注意: 既存マクロは「並べ替えた後の**次の行**」を運賃とみなしていました（`=S(i) - T(i+1)`）。
> 運賃行が抜けている受注があると、そこから下がずれて誤判定が出ていました（例: ㈱ワシダ 北九州支店、㈱昭和トラスト 広島営業所）。
> 受注番号でまとめるとこのずれは起きません。

### 4.3 単価チェック
- 住所1の**先頭3文字**で県を判定する（「福岡市」「北九州」「鹿児島」は3文字のまま扱う）。
- 想定運賃 = 県別単価（円/kg※）× 商品行の重量。`ROUND` で整数にする。
- 請求運賃 = 運賃行の売上金額
- 想定運賃 = 請求運賃 → OK、違えば NG（例外リストにあれば「例外OK」）

※ 単価表の見出しは「円/ℓ」ですが、計算には重量（kg）を使っています。既存ツールに合わせています。

**県別単価表（ver.0.02 時点。本体では表として持ち、編集できるようにする）**

| 県 | 単価 |
|---|---|
| 福岡県・福岡市・北九州・佐賀県 | 13.6 |
| 熊本県・長崎県 | 16.1 |
| 大分県・鹿児島・宮崎県 | 19.8 |
| 山口県 | 17.3 |
| 広島県 | 17 |
| 岡山県・島根県・鳥取県 | 18 |
| 香川県・愛媛県・徳島県・高知県 | 19.5 |
| それ以外（沖縄県など） | 未定義 → 要確認 |

### 4.4 過去データでの検証結果（2026/04/01〜04/27）
- 受注 799 件 → 一致 728 / 単価NG 48 / 運賃行なし 23
- 単価NG 48 件は、既存の付け合わせシートで「×」になった 48 件と**完全に一致**（ロジックが正しい裏付け）
- 実装後は、同じデータを入れて同じ数字になるかを必ず確認する

### 4.5 出力のイメージ
- 画面／シートの上部に件数サマリ（OK・例外OK・NG・運賃なし・要確認）
- NG・要確認の行だけを赤系で一覧表示（受注番号、出荷日、納入先、県、重量、想定運賃、請求運賃、差額）
- NG の行から「例外に登録」できると、例外リストが育てやすい（あれば便利。必須ではない）

## 5. 未確定・要確認事項（実装前後にユーザーに聞く）

1. **加工前CSVの列構成**: クラウドで見たのはマクロ実行後のデータ（21列）だけです。既存マクロは元の列を大量に削除しているため、元の列名・列順はサンプルCSVで確認してください。必要な列は次のとおりです。
   売上日・売上番号・伝票種類・受注番号・出荷日・納入先コード・納入先名・住所1・運送会社名・商品名・重量・売上金額
2. **離島（運送会社＝博運社）**: 12件がすべて単価NG（実質 28〜40円/kg）。「博運社はまとめて単価チェックから外す」か「離島用の単価を持つ」か。
3. **小口（80kg以下）**: 35件が固定額（1,380〜3,000円）で請求されていて NG。一方で 80kg 以下でも単価どおりの受注が44件ある。納入先ごとに決まっているのか、別のルールがあるのか。
4. **沖縄県**: 単価表にない。単価を追加するか、例外にするか。
5. **例外リストの置き場所**: 受ける君本体の中にシートとして持つか、別ファイルにするか。
6. はこぶ君「分析表発行チェックシート」の中身は今回は作らず、ボタンだけ置く（押せない状態）という理解でよいか。

## 6. 例外リスト素案（`例外リスト_素案.xlsx`）の中身

| シート | 内容 |
|---|---|
| 集計と読み方 | 区分ごとの件数・所見・使い方 |
| 例外リスト | 納入先コード単位で60件。「確認（○/×）」列にユーザーが印を付ける |
| NG明細 | 受注単位で71件（単価NG 48 ＋ 運賃なし 23） |

| 例外区分 | 件数 | 照合時の扱い（案） |
|---|---|---|
| 運賃行なし | 23 | 運賃行がなくても OK（引取・合積み等） |
| 離島（博運社） | 12 | 単価チェックの対象外 |
| 小口（80kg以下） | 35 | 単価チェックの対象外 |
| 単価表に県なし | 1 | 単価チェックの対象外 |

- 広島舗材㈱ は3受注のうち1件だけ運賃なし → 納入先単位ではなく、**その受注だけの例外**にするのが妥当そう
- 同じ納入先で毎回運賃なし（住友金属鉱山 菱刈鉱山 など）は、納入先単位の例外で問題なさそう

再作成する場合:
```
pip install openpyxl
python make_exception_draft.py 運賃チェックシートver.0.02.xlsm 例外リスト_素案.xlsx
```
（入力は、マクロを実行した後の「張り付けシート」が入った xlsm）

## 7. 参考：既存ツールの仕組み（解析結果）

- **運賃チェックシート ver.0.02（xlsm）**: bead の CSV を貼り付けてマクロ「運賃チェック」を実行する。不要な列を削除し、在庫以外・引取・自社便の行を削除する。出荷日と納入先で並べ替え、住所の先頭3文字から県を出して単価を割り当てる。想定運賃と「次の行」の売上金額を比べ、差額が0でないセルを赤くする。1〜99kg の重量は黄色で表示する。
- **運賃付け合わせ ver.0.02（xlsx）**: 運賃行だけを貼り付けて使う。売上金額÷重量で bead の単価を出し、納入先マスタ（17,113件）から住所を引いて県別単価と比べる（〇/×）。数量単位が「式」の運賃行はすべて×になる。
