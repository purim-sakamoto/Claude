# 路線便 荷札・送り状 発行システム 要件定義書

- 版: 0.1（初版ドラフト）
- 作成日: 2026-09-29
- 対象業務: 路線便（JPロジスティクス・博運社・九州西濃運輸 ほか）向けの荷札・送り状の印刷
- 参考資料:
  - 伝発名人 設定書き出し（`repositorydata.xml`）
  - 現行 BEAD 出力データ（`okuri.txt` / `syuka.txt`）
  - 路線便のルール（Excel、2026.4.10 版）
  - 荷札発行システムの仕様・要件メモ（Word）

---

## 1. 目的

伝発名人を使った現在の荷札・送り状の発行には、次の問題がある。

1. 送り状用（1件1行）と荷札用（1件複数行）で、BEAD からのデータダウンロードと印刷を何度も行っている。
2. 荷札の枚数を、一覧から人が行を選んで決めている。BEAD は明細1行につき常に10行を出力しており、発行枚数の項目は使えない。
3. 荷札の用紙の色（水色・黄色・アドブルー）の付け替えが多い。
4. 運送会社の振り分けにはルールと例外がある。一部は目視で差し替えている。

本システムは、**BEAD の受注明細検索から出したデータを1回取り込むだけで**、運送会社の判定、荷札の色と枚数の判定、送り状と荷札の印刷、印刷済の管理までを行う。これで上記の問題を解消する。

## 3. 現状（As-Is）の整理

### 3.1 データの流れ

```
BEAD ──(送り状用 1件1行)──▶ O:\192.168.10.176_okuri.txt ─┐
     ──(荷札用 1件×10行)──▶ O:\192.168.10.xxx_syuka.txt ──┤─▶ 伝発名人 ─▶ ドットプリンタ
                                                             │   (行を選択して印刷。印刷済フラグを管理)
```

- 形式は固定長テキスト（Shift_JIS、1レコード488バイト＋改行）。
- `帳票コード` の項目で、どの帳票で印刷するかが決まる。
  - 4000001 = 荷札、4000003 = 博運社、4000008 = 西濃、など。
  - 過水系は 3000011 = 過水荷札、3000002 = 引取、など。
- 荷札用データは、明細1行につき `重複制御番号` を連番にして **常に10行** 出力されている。
- 人が一覧から必要な枚数だけ選んで印刷している。例：×5 の商品なら10行中の5行を選ぶ。
- 伝発名人には条件分岐のスクリプトは設定されておらず、判定はすべて BEAD 側か人が行っている。

## 4. 入力データ要件

### 4.1 取込データ

- BEAD の **受注明細検索** から出力したファイル（CSV または Excel）を、1日1回または必要な都度取り込む。
- 1回の取込で、送り状と荷札の両方を作る。

### 4.2 必要な項目

| 必須 | 項目 | 用途 |
|---|---|---|
| ◎ | 受注番号（または出荷番号）・行番号 | まとめる単位、印刷済の管理キー |
| ◎ | 納入日（出荷日） | 印刷対象の抽出 |
| ◎ | 納品先コード・名称1〜2 | 印字、例外判定 |
| ◎ | 納品先郵便番号・住所1〜3 | 印字、エリア判定 |
| ◎ | 納品先電話番号 | 印字 |
| ◎ | 商品コード・商品名 | 印字、荷札の色判定 |
| ◎ | 個数・入目・数量・単位 | 枚数計算、印字 |
| ○ | 重量 | 送り状への印字 |
| ○ | 運送会社（BEAD で指定されている場合） | 運送会社の判定 |
| ○ | 備考 | 着日・回収有無の判定と印字 |
| ○ | 納入区分（立替・元払・引取） | 引取を除外する、送り状への印字 |
| ○ | 得意先コード・名称 | 印字、例外判定 |

> **要確認**: 受注明細検索の実際の出力サンプル（数件分）。項目名と並びを確定する。

## 5. 機能要件

### F1. データ取込

- F1-1: 受注明細検索の出力ファイルを選んで取り込む。前回のフォルダを覚えておく。
- F1-2: 文字コード（Shift_JIS）と項目の並びは設定ファイルで定義する。BEAD 側の出力項目が変わっても、設定の変更だけで対応できるようにする。
- F1-3: 納入区分が「引取」の明細は、路線便の対象から外す。一覧には除外として表示する。
- F1-4: 同じデータを再度取り込んでも、印刷済の状態は維持する（受注番号＋行番号をキーにする）。

### F2. 運送会社の判定

次の優先順で、出荷単位（受注番号単位）に運送会社を決める。

| 優先 | 判定 | 内容 |
|---|---|---|
| 1 | 画面での手動指定 | 利用者が一覧で変更した値。最優先で、再取込でも維持する |
| 2 | 例外リスト | 納品先（と商品）で運送会社を固定する（6.2） |
| 3 | BEAD での明示指定 | 運送会社の項目、または備考に書かれた運送会社名 |
| 4 | 離島 | 対馬市は対州海運（＋博運社）、壱岐市は壱岐海運、五島市・南松浦郡上五島町・北松浦郡小値賀町・佐世保市宇久町は野母商船 |
| 5 | JP商品 | アドブルーBIB・MGCポリ缶は JPロジスティクス。ただし JP の配送不可エリアは 6 に回す |
| 6 | 一般 | 九州・離島は博運社、本州以北は九州西濃運輸 |
| 7 | 回収による補正 | ポリ缶回収があり、配送先が長崎・佐賀（※3 の回収可エリアを除く）の場合は九州西濃運輸（回収を基準にする） |

- F2-1: 判定結果と BEAD の指定が食い違う場合、その行を強調表示する。人が目視で確認するための機能。
- F2-2: 判定の根拠（例：「例外リスト」「離島：壱岐市」「回収補正」）を一覧に表示する。
- F2-3: 例外リストで「自社便」になった出荷は、印刷の対象から外す。一覧には表示する。
- F2-4: 判定ルールのうち、エリア一覧・例外リスト・JP商品一覧は、Excel か CSV の **マスタファイル** として持つ。プログラムを直さずに更新できるようにする。

### F3. 荷札の種類（色）の判定

| 荷札種類 | 対象 |
|---|---|
| 水色（弱粘着） | ポリ缶（硫酸系を除く） |
| 黄色（強粘着） | ポリ缶（硫酸系）、その他すべて（段ボール・袋・ドラム・コンテナ） |
| アドブルー専用 | アドブルーBIB |

- F3-1: 商品コードから荷札種類を引く **商品マスタ**（商品コード → 荷札種類）を持つ。
- F3-2: 商品マスタにない商品は、商品名から仮に判定し、「要登録」として強調表示する。
  - 「ＡｄＢｌｕｅ」を含む → アドブルー
  - 「ポリ缶」と「硫酸」を含む → 黄色
  - 「ポリ缶」を含む → 水色
  - それ以外 → 黄色
- F3-3: 一覧の画面から、商品マスタへ登録・変更できる。
- F3-4: **色の統一に対応する。** 荷札をすべて水色に統一する案があり、2026年10月にテストして導入するか判断する予定。このため、次の2つの運用を設定の切替だけで行えるようにする。
  - 色分けモード: F3-1〜F3-3 のとおり、3種類で振り分ける（現行）。
  - 統一モード: すべての荷札を1種類（既定は水色）として扱う。F6-2 の色指定は不要になり、1回の一括印刷で済む。
  - 統一の対象（アドブルー専用荷札も含めるか）は設定で選べるようにする。
  - どちらのモードでも、発行枚数（F4）と印字内容（F5）は変わらない。

### F4. 荷札の発行枚数

- F4-1: 商品ごとに `発行枚数 = min(個数, 10)` とする（11個以上でも10枚）。
- F4-2: 画面で出荷ごと・商品ごとに枚数を手動で変更できる。
- F4-3: 個数が0や小数の場合（ローリーやトン単位の数量など）は枚数0とし、確認対象として強調表示する。

### F5. 荷札の印字内容

- F5-1: 同じ納品先への荷札には、**その納品先で受注しているすべての商品** を共通で印字する。
  - 例：a ×5、b ×8、c ×15 の場合、a 用の5枚・b 用の8枚・c 用の10枚のどれにも a・b・c の3商品を印字する。
- F5-2: 印字項目（現行 4000001 準拠）は、納品先住所1〜3、納品先名称1〜2、商品名＋個数（最大3行）、合計個数（大きな文字）。
- F5-3: 「同じ納品先」の単位は出荷番号（受注番号）とする。同じ納品先・同じ納入日で出荷番号が複数ある場合にまとめるかは要確認（9章）。

### F6. 印刷指示画面

- F6-1: 納入日（出荷日）で絞り込んだ出荷の一覧を表示する。表示項目は、運送会社、納品先、商品、荷札種類、枚数、判定根拠、印刷状態。
- F6-2: 荷札は **色を指定して一括印刷** できる。選択肢は「水色のみ」「黄色のみ」「アドブルーのみ」。
  - 運用例：「10/1 水色のみ」で印刷する → 用紙を黄色に替えて「10/1 黄色のみ」で印刷する。
  - 1つの納品先で色が混ざっていても、色ごとの枚数はシステムが自動で振り分ける（F3・F4 の結果を使う）。人の選別は不要。
- F6-3: 送り状は **運送会社を指定して一括印刷** できる（1出荷につき1枚）。
- F6-4: 一覧から任意の出荷を選び、個別に印刷・再印刷できる。
- F6-5: 印刷前に、画面でプレビューを表示できる。
- F6-6: 印刷する順番は、運送会社 → 出荷番号 → 商品の順を既定とする。

### F7. 送り状の印刷

- F7-1: 運送会社ごとの帳票レイアウトで、1出荷につき1枚を印刷する。
- F7-2: 印字項目は各社の現行レイアウトに準拠する。主な項目は、納入日、郵便番号、住所、名称、電話、商品名（最大3行）、個数合計、重量、備考1〜2。
- F7-3: 商品が明細行数を超える場合の扱いは要確認（9章）。
- F7-4: 対州海運は「対州海運＋博運社」の運用とし、どの帳票を発行するかは要確認。

### F8. 印刷済の管理

- F8-1: 印刷した荷札と送り状を「印刷済」として記録する。記録するのは、出荷番号、帳票種別、荷札種類、枚数、日時。
- F8-2: 一覧で未印刷・印刷済を区別して表示する。一括印刷の対象は未印刷のみとする。
- F8-3: 印刷済のものを再印刷する場合は確認を出す。紙詰まりなどに備えて、枚数を指定した部分再印刷もできる。
- F8-4: 印刷済の記録は、PC のローカルファイル（SQLite など）に保存する。共有フォルダに置くかは要確認。

### F9. 印字位置の調整

- F9-1: 帳票ごとに、印字全体の X・Y オフセット（0.1mm 単位）を設定できる。
- F9-2: 帳票ごとに、テスト印字（枠や目盛りの印刷）ができる。
- F9-3: 帳票レイアウト（項目・座標・文字サイズ）は設定ファイルで持ち、後から調整できる。

## 7. 非機能要件

| 性能 | 1日分（数百行）の取込から一覧表示まで数秒以内 |
| ログ | 取込・判定結果・印刷の履歴を日付ごとのファイルに残す |
| データ保護 | 納品先の住所・電話番号を含むため、取込データと印刷履歴は社内 PC か共有フォルダにのみ置く。Git 等には登録しない |

## 8. 開発の進め方（案）

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| 0. 試作 | 荷札1種を固定データで FMPR に印刷し、位置合わせを確認する | 現行の荷札と重ねてずれがない |
| 1. 本番最小構成 | 取込、運送会社判定、荷札（色分けと統一の両モード。10月テストの結果で既定を決める）、送り状3社（博運社・西濃・JP）、印刷済管理 | 1日分の実データで伝発名人と同じ結果が出る |
| 2. 離島対応 | 壱岐海運・対州海運・野母商船の送り状 | 各社の現物帳票に正しく印字できる |
| 3. 並行運用と切替 | 伝発名人と並行運用して差異を確認し、伝発名人の路線便を停止する | 1〜2週間、差異がない |

技術スタックは、ローカルでプロジェクトを立ち上げる際に決める。推奨は Python（GUI と Windows 印刷）を exe 化する方式。Excel VBA でも実現できる。
